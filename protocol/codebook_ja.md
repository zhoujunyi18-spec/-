# コードブック v0.2（先導調査用・未凍結）

## 統計単位

主単位はレビュー。抽出単位は評価命題・比較命題。1レビュー内の同一要素の反復は1回と数える。異なる下位要素に正負があれば上位要素はmixedになるため、下位対象と根拠も残す。mixedは中立・不確実とは異なる。

## 要素

- B 戦闘・成長：戦闘、難易度、育成、装備、スキル。日程による育成制約も含む。
- E 探索・誘導：マップ、移動、ダンジョン構造、道案内。戦闘自体の反復はB。
- N 物語・人物：物語、人物像、対話、交流イベント。外見だけの評価はA。
- U UI・操作：メニュー、可読性、操作、セーブ・ロード操作の手間。セーブ消失はT。
- A 視聴覚：グラフィック、美術、音楽、声、映像表現。UIの見た目はUに統一する。
- T 技術的品質（補助）：クラッシュ、フレームレート、データ消失、起動・接続制約。
- O その他（補助）：価格、販売方法など。要素が特定できない全体賛否は無理に割り当てない。

初期5分類にTとOを補助コードとして追加。主分析は5分類、T/Oは残余として別掲。MDAの既成分類とは呼ばない。ゲーム性やシステムの語だけでBを推定しない。

## 現在評価

positive / negative / mixed。評価がない場合はラベルを作らない。「易しい」「変わった」「追加された」だけでは良否を推定しない。推薦フラグは判断根拠として見せない。本文の「面白い」は対象が特定できる場合のみ要素に付与する。報告される現象を事実認定するのではなく、投稿者の評価表現をコード化する。

## 明示的旧版比較

旧版と対象リメイクの共通要素について性質・機能の対応を本文から復元できる場合。比較対象、要素、関係の根拠が必要。「原作プレイ済み」「懐かしい」「良いリメイク」だけは除外。「以前」「昔」は文脈が旧版を特定する場合のみ採用。他ナンバリング、他作品、デモ、同じリメイクのパッチ前との比較は除外。

比較関係（addition / change / retention / deletion / coexistence）と評価を区別する。相対方向はpositive / negative / mixed / no_change / unevaluated。価値判断のない変更・追加はunevaluated、明示的な性質維持はno_changeとする。保持を褒めていても改善とは呼ばない。保持や変更に対する賛否はcomparison_valenceに別記し、現在評価を機械的に流用しない。「保留」は不確実性として別記する。先導注釈の関係は短縮表現で、正式注釈では下位対象の記述を追加する。

参照版は明示版（SFC、PS、PS2、PSP等）を残し、旧版であることは明確だが個別版が不明ならunspecifiedとする。複数版はmultipleにして名称を併記する。版を推測で確定しない。

## 二つの評価の対応

「原作より良い」だけから現在positiveを付けない。現在評価と比較評価は独立の原文根拠を要する。両方があっても上位分類が同じだけでは対にしない。同一下位対象・対応する命題の範囲で結び付けられる場合に限り不一致事例とする。

## 検証と停止

正式4作品の先導標本120件と、除外ケースSO2Rの診断30件はAIが読解した未検証ラベル。人手ラベルではない。別標本200件（正式4作品各50件）は非重複の盲検用として確保する。ルール凍結後に人手で付与し、二者一致・不一致・根拠対応を点検する。比較のprecision/recall/F1、方向のmacro-F1、複合タプルの正解率を別々に報告する。稀な陽性は追加の濃縮診断標本で調べ、母集団割合には混ぜない。

『空の軌跡 the 1st』ではFCの旧版（PC・PSP等）と他の軌跡シリーズ作品の比較を分ける。『空の軌跡SC』等は原作FCの旧版ではない。「前作」だけで参照版を推定しない。Steamの別配信AppID 3447040は自動合算しない。

運用上の暫定移行条件は比較検出precision/recall各0.80以上、方向macro-F1 0.75以上。普遍的な学術基準ではなく、誤分類が主結論を左右するリスクに対応する事前判断である。陽性が少なすぎるときは達成認定せず増標本。未達なら再設計・対象縮小・手動コーディングへの切替。全量の意味ラベル付与は未実施。
